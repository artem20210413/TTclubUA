## IDEA-001 — Розширена статистика для адмінів

**Статус:** 💡 нова · **Додано:** 2026-11-22

Зараз адміни мають `GET /api/system/user-stats` (кількість користувачів, нові, активні за останню
годину, з авто й без), фінансову статистику сезону, кількість заявок, щомісячну статистику спотингу
в Telegram і статистику повідомлень у щоденному дайджесті. Кандидати нижче рахуються з даних, які
вже є в базі, якщо не зазначено інше.

### Пріоритетні кандидати
- [ ] Боржники сезону: активні учасники без записів у `finances` від початку сезону; частка тих, хто сплатив; середній внесок.
- [ ] Неприв'язані платежі Monobank: `mono_transactions`, які застрягли в `pending`/`rejected` або мають `user_id = null`.
- [ ] Неповні профілі: без `telegram_id` (не може увійти за кодом, не отримує повідомлень від бота), без авто, міста, фото, дати народження.
- [ ] Авто учасників на продаж: `external_cars` з `user_id` і `is_sold = false`.

### Активність у застосунку (`personal_access_tokens`)
- [ ] DAU / WAU / MAU і співвідношення DAU/MAU (зараз лише «за останню годину»).
- [ ] Розподіл платформ і версій застосунку (`app_platform`, `app_version`).
- [ ] «Сплячі» акаунти: жодного разу не входили в застосунок або неактивні 60+ днів.

### Telegram-чат
- [ ] Тренд активності чату по днях/тижнях (`daily_digests.total_messages` уже зберігається щодня).
- [ ] «Мовчуни»: мають `telegram_id`, але не писали в головний чат N днів.
- [ ] Активність по годинах / днях тижня (найкращий час для анонсів).

### Push-сповіщення
- [ ] Частка користувачів з увімкненими push (`fcm_tokens.active`), окремо по платформах.
- [ ] Частка прочитаних push: `read_at` / усього в `notifications`, окремо по `type`.

### Склад клубу
- [ ] Автопарк: розподіл за поколіннями, моделями, кольорами; кількість учасників без TT (`is_tt = false`).
- [ ] Вік (`birth_date`) і стаж у клубі (`club_entry_date`), найближчі річниці членства.
- [ ] Воронка заявок: подано → схвалено, середній час до схвалення (`registrations`).
- [ ] Відтік: учасники, деактивовані за період (дати з `audits`).

### Спотинг і розіграші
- [ ] Теплова карта спотів за `mentions.latitude` / `longitude`.
- [ ] Кого найчастіше ловлять (`caught_user_id`) і авто, які жодного разу не спотили.
- [ ] Розіграші: унікальні учасники, найчастіші учасники, частка доданих вручну.

### Ринок (Autoria)
- [ ] Ціни на TT: середня ціна за поколінням/роком, продано за місяць, середній час до продажу.

### Потрібен новий збір даних
- Явка на події: участь у подіях ніде не фіксується (потрібна реєстрація, RSVP).
- Заявки на покупку товарів: їх лише відправляють у Telegram і не зберігають.

### Нотатки до реалізації
- `SystemController::systemUserStats` повертає `response()->json(...)` напряму, а не через обгортку `success()` — привести до конвенції, якщо розширюватимемо цей ендпоінт.
- `MentionEloquent::getMostActiveDayWeek` вибирає `day`, а читає `$result->date` (завжди повертав би сьогоднішній день тижня); зараз не використовується.
